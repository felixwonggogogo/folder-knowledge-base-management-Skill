# 工作流程

## 所有模式共用的澄清门

本技能只面向个人本地资料。首次制定分类时按 [场景选择题](scenarios.md) 补用途；同级主要维度一致。用 policy-get 读取已有规则，默认模板只是候选，用户明确无偏好时采用。先检查/应用场景与 [独立词表](vocabulary.md)，再按当前 policy_revisions 标注；规则变更列受影响文件，不自动调整原路径。

先按 [澄清与授权门](interaction-gates.md) 确认目标路径、任务模式、内容访问范围和写入/整理授权。用户说“整理一下”但没有给出目录或操作范围时，先主动询问；不得默认当前工作目录，也不得先扫描再问。明确建库请求可以包含创建知识库自己的索引，但不自动包含移动/重命名原文件。用户明确要求该范围内实际整理、改名、移动或去重，且执行规则确定时，操作计划校验通过即可执行，不逐项要求额外批准。删除始终需要针对具体目标的明确同意。

## 建库

“建库”允许写索引，移动/改名来自明确整理意图和确定范围。目录不明时问路径，禁止整盘扫描。

1. 预检工具、解析能力、内容进入模型的许可。
2. `scan` 创建/更新清单，记录完全重复文件、完全重复目录树、解析失败/截断、目录和排除项。文件重复按 SHA-256；目录重复比较递归相对路径、文件内容哈希和空目录，不把相似版本判断为重复。
3. `dump` 分批读档案；缓存不覆盖部分用宿主实际解析工具读取。未变标注复用。
4. 分类定义/MECE 检查；生成标题、摘要、标签、原文依据、覆盖情况和置信状态。
5. `annotate` 导入；`index` 或 `refresh` 生成根入口、AI 使用说明、集中式目录导航、manifest 和真人离线 HTML。原生工具识别的额外事实写入证据字段，不因此宣称 helper 全文搜索覆盖了额外内容。
6. 报告扫描/跳过/失败/截断数量、重复组数、已隔离数、可恢复 run-id、待确认项及索引路径。

## 整理与恢复

普通文件整理计划列 file_id、旧路径、新路径、sha256 和原因，并绑定库根路径。先 `plan-check`；`apply` 默认仍只校验，`--execute` 才修改文件。用户已明确要求本范围内实际整理/移动时，校验通过即可执行；只有建库或方案请求时交付计划，不改动原文件。

现有子文件夹允许改名或整体移动：用 `directory-plan --src ... --dst ... --reason ... --save-as ...` 生成完整树哈希与 v2 计划，读依赖风险，再 `directory-plan-check` 和 `directory-apply --execute`。命名编号按用户习惯和 [双人群导航](navigation.md) 决定。文件阶段与目录阶段分开；每个阶段完成后刷新，再生成下一阶段计划。计划生成和执行语法见 contracts.md，恢复仍使用同一个 `rollback`。

### 精确重复项隔离

只有用户明确提出去重，才调用 `quarantine`。先让用户意图、路径范围和嵌套目录处理范围明确；预览计划将保留项与隔离项按路径列出。完全相同的文件/目录以 SHA-256/完整目录清单证明；人工位置锁定项优先保留，多个锁定项或扫描不完整时跳过。执行后使用同卷重命名移入 `.filedb/quarantine/<run-id>/`，不覆盖、不合并、不删除；日志保存原路径、哈希和阶段。扫描并更新索引后，隔离项从普通检索结果排除，但可用 run 日志定位。

恢复使用 `restore-quarantine --root <库根目录> --run-id <run-id>` 预检，确认原位置无冲突后加 `--execute`；若文件或目录在隔离后被改动，停止并报告。隔离区没有自动过期或清理策略；用户若要永久删除，单独列出具体项目并取得明确同意。

helper 排他创建目标、复制、校验哈希、核对源未变后移除源。可能短暂两份；数据库与磁盘不原子提交。不保证 ACL、硬链接、inode 或全部扩展属性语义，有这些要求用专用宿主工具或只索引。

日志先于操作写入，逐项更新阶段，失败立即停止。恢复前先查看 run；`rollback` 默认预检，加 `--execute` 才恢复。原位置占用或目标内容已改停止并说明冲突。反向移动恢复路径；不保证撤销后来人工标注。恢复后复扫和重建索引。

## 纳入新资料

确认上传附件/库外文件在宿主的真实路径和用户指定库。用宿主工具复制到选定库内位置（例如收件箱），不覆盖，检查哈希，记录原路径/附件 ID。源保留按用户选择。helper 不复制库外数据、不抓取 URL，也不上传云端。

复扫沿用现有 taxonomy/词表，确实新主题才建议结构修订。副本是独立 file_id；相同哈希仅列重复组。

## 检索与维护

先读取 `AI_README.md` 与 `AI_INDEX.md`，再运行 `status`。有变化且允许维护时默认用 `refresh`；需要校验所有源文件字节时用 `refresh --full`。只读查询允许直接读取实际源文件并报告索引过期，不强行写入。

运行 `query --query ... [--folder ...] [--tag ...] [--semantic-status ...]`，依 `total/next_offset` 读完相关分页；复杂问题用不同关键词和条件交叉检索。经常复用的条件可用 `view-save` 保存、`view-list` 查看、`query --view-name` 执行并分页、`view-delete` 移除视图定义。分类/解析问题用 `pending` 翻页，重复组用 `duplicates --kind file|directory --offset N` 翻页。再通过 `dump --file-id ...` 检查来源哈希和覆盖，回到源文件定位核验。精确回答附当前路径及页/行/章节/时间位置；无可定位信息时说明。空搜索、抽样、首 100 条或缓存截断不能证明事实不存在。

文件锁/同步中变化先等待宿主允许的短时重试，再验证实际哈希；仍不稳定记待处理，不发布与当前源不一致的档案。
